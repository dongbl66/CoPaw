# 项目周报生成技能

当你需要为智能投标助手（AITender Claw）项目编写或更新周报时，使用本技能。

## 技能目标

- 接收用户用自然语言描述的项目进展信息
- 自动将信息整理并填充到标准的周报模板中
- 保持周报格式的一致性和完整性
- 生成可直接使用的Markdown格式周报

## 周报模板结构

周报包含以下模块，每个模块都有明确的填写说明：

### 一、项目里程碑与版本交付

**填写说明：**
- 记录所有关键里程碑的计划日期、实际完成日期和状态
- 里程碑包括：前后端开发、技能开发、各场景研发交付、效果验证、产品封装、产品发布、试点推广等
- 状态分为：未开始、进行中、已完成
- 记录当前版本和本周期发布版本信息

**示例填写内容：**
```
| 里程碑 | 计划日期 | 实际完成 | 状态 | 备注 |
|--------|----------|----------|------|------|
| 施工类场景研发交付 | 5.22 | 5.22 | ☑ 已完成 | |
| 施工类场景评标专家效果验证 | 5.30 | 进行中 | ☐ 未开始 ☑ 进行中 ☐ 已完成 | 正在6个项目实测 |
```

### 二、整体进展概述

**填写说明：**
- **项目进度概览**：总体进度百分比、功能模块完成数、Bug修复数、代码提交次数、测试覆盖率等关键指标
- **整体进展描述**：2-3段话概括项目整体进展，包括项目目标、重要成果、关键进展和挑战

**示例填写内容：**
- 总体进度: 60% 完成
- 功能模块完成数: 3 / 5

本项目聚焦供应链管理部业务管理效能提升，选取"AI辅助评审"场景开展技能化探索...

### 三、本周进展

**填写说明：**
- **已完成工作**：按功能开发、Bug修复、文档完善、测试工作等分类列出本周完成的具体工作，使用复选框标记
- **技术亮点**：描述本周的技术突破、架构优化、性能提升等
- **问题与解决方案**：使用表格记录遇到的问题、影响范围、解决方案和当前状态

**示例填写内容：**
- [x] **功能开发**
  - 施工类场景版本开发完成
  - 完成规则解析、信息提取等8项通用技能的迭代优化

### 四、下周计划

**填写说明：**
- **工作安排**：按优先级高、中、低分类列出下周计划开展的工作
- **风险与应对**：使用表格记录潜在风险、风险等级和应对措施

**示例填写内容：**
- [x] **优先级高**
  - 建立主评+复评双审机制
  - 将评审项调整为并行运行

### 五、个人分工情况

**填写说明：**
- **团队分工**：使用表格记录团队成员、负责模块、本周工作和下周计划
- **个人贡献统计**：可选，用于量化个人贡献（代码行数、提交次数、解决Issue数等）

### 六、需要协调的事项

**填写说明：**
- 列出需要上级或其他团队支持、协调的事项

## 使用方式

### 场景1：新建周报

当用户想要创建一份新周报时，按以下步骤操作：

1. 询问用户：报告周期、报告日期、报告人
2. 让用户用自然语言描述本周项目进展的所有相关信息
3. 基于之前创建的周报模板（位于 `docs/周报模板.md`），将用户提供的信息整理填充到对应模块中
4. 在 `docs/` 目录下生成新的周报文件，命名格式为 `周报_YYYYMMDD-YYYYMMDD.md`

### 场景2：更新现有周报

当用户想要更新已有的周报时，按以下步骤操作：

1. 先读取现有周报文件
2. 让用户用自然语言描述需要更新或添加的内容
3. 根据用户描述，判断内容应该更新到哪个模块
4. 只修改相关模块，保持其他模块内容不变
5. 保存更新后的周报

### 场景3：增量更新周报

当用户说一段话想要更新周报时，按以下步骤操作：

1. 理解用户输入的内容属于哪个模块
2. 将内容智能整理后填充到对应模块
3. 如果内容涉及多个模块，分别填充到相应位置
4. 保存更新后的周报

## 智能内容分类指南

当用户输入自然语言描述时，按以下规则自动分类到对应模块：

| 用户描述特征 | 对应模块 |
|-------------|---------|
| 提到"里程碑"、"交付"、"版本"、"计划日期"、"完成日期" | 一、项目里程碑与版本交付 |
| 提到"整体进度"、"总体进展"、"项目概况"、"关键指标" | 二、整体进展概述 |
| 提到"本周完成"、"已完成"、"做了"、"技术亮点"、"遇到的问题" | 三、本周进展 |
| 提到"下周计划"、"将要做"、"准备"、"风险" | 四、下周计划 |
| 提到"分工"、"谁负责"、"团队成员" | 五、个人分工情况 |
| 提到"需要协调"、"需要支持"、"跨部门" | 六、需要协调的事项 |

## 输出要求

1. **格式标准**：严格按照 `docs/周报模板.md` 的格式输出
2. **内容完整**：确保所有模块都有合适的内容，没有遗漏
3. **语言简洁**：表达清晰简洁，避免冗余
4. **数据准确**：准确记录日期、数据、状态等信息
5. **文件保存**：周报文件保存在 `docs/` 目录下

## 调用示例

### 示例1：创建新周报

**用户输入：**
```
我要写一份周报，周期是5月25日到5月31日，今天是6月1日。本周施工类场景版本开发完成，UI界面优化全部落地，完成了8项通用技能的迭代优化，整体处理效率提升20%，评审准确率提升10%。在供应链管理部部署了系统，正在6个项目实测。初评准确率80%，详评准确率70%。下周要建立双审机制，并行运行评审项，推进服务货物类场景研发。
```

**技能执行：**
1. 基于模板创建新周报
2. 将信息分类填充到对应模块
3. 保存为 `docs/周报_20260525-20260531.md`

### 示例2：更新现有周报

**用户输入：**
```
更新一下周报，刚才忘了说，我们还确定了异步并行和分布式并行两种技术方案来解决性能问题，正在进行可行性验证。
```

**技能执行：**
1. 读取现有周报
2. 将内容添加到"三、本周进展"的"问题与解决方案"或"技术亮点"部分
3. 保存更新后的周报

## 注意事项

- 如果用户提供的信息不完整，先填充已有内容，缺失部分留空并提示用户补充
- 保持周报的专业性和客观性
- 数据要准确，特别是日期、百分比、数量等
- 里程碑状态要及时更新
- 风险应对措施要具体可行
