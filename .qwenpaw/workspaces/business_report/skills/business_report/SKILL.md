# 商业情报与招投标收集助理

## 技能描述

通过浏览器检索公开网页，先采集石膏/建材行业相关线索，再打开关键页面提取事实信息，基于事实生成 HTML，最后根据执行结果输出结构化 JSON。

## 适用场景

- 生成石膏商业报告
- 监控建材行业（石膏板）的招投标与获客信息
- 收集特定竞争对手（如可耐福、龙牌、北新建材）的商业动态
- 基于公开网页生成市场情报分析报告

## 依赖 Skills

执行过程中可以合理参考以下 skills 的做法：

- **Agent Browser**：用于浏览器自动化、页面导航、结果页与详情页采集

不要机械复述其他 skill 内容；仅在需要浏览器操作参考其工作流。

## 执行原则

- 全程以公开可访问网页为数据来源
- 先记录事实，再做归纳，不得跳过“打开页面提取关键信息”这一步
- 报告中的分析必须建立在已提取的事实之上，不得编造结论
- 除记录事实外，还要同步记录执行过程统计信息，用于报告首页概览与图表生成
- 最终交付结果优先输出为“结构化结果 + 落地产物路径”
- 落地产物仅包含 HTML 报告
- 不得生成、展示或在 `display_content` 中记录 `market_data.json`

## 执行指令

作为 OpenClaw Agent，按以下顺序执行任务。

### 阶段一：浏览器初始化

1. 使用当前环境可用的浏览器自动化能力。
2. 打开并导航至目标搜索入口：`https://www.baidu.com/`。
3. 准备逐个执行搜索词。

### 阶段二：搜索结果采集

依次搜索以下查询词。每个查询词最多保留前 10 条有效结果。

执行本阶段时，同步记录以下统计口径，供后续概览与图表使用：

- 检索词总数
- 每个检索词返回的结果数
- 每个检索词最终保留的结果数
- 去重前结果总数与去重后结果总数
- 涉及的来源站点数量

**获客信息查询词：**

- `site:ccgp.gov.cn 石膏 | 建材`
- `site:chinabidding.com.cn 泰安 建材`
- `intitle:石膏 招标 | 采购 | 中标`
- `泰安新开楼盘`

**竞对品牌查询词：**

- `可耐福 新闻`
- `龙牌建材 新闻`
- `北新建材 新闻`

对每条保留结果，至少记录：

- 标题
- 搜索摘要
- 跳转前或实际目标链接
- 来源站点
- 对应查询词
- 初步分类（招标 / 中标 / 采购 / 政策 / 区域需求 / 竞对动态 / 其他）

优先保留以下来源：

- 政府采购网
- 公共资源交易平台
- 政府/住建官网
- 企业官网
- 主流财经或行业媒体

默认降权或过滤以下结果：

- 视频聚合页
- 百度百科、黄页、爱企查类弱相关页
- 泛营销页
- 与石膏/建材主题弱相关的噪声结果

### 阶段三：打开页面并提取关键信息

不要只停留在搜索结果页。对筛选后的重点结果，进一步打开原页面，提取关键信息。

执行本阶段时，同步记录以下统计口径：

- 实际打开页面数
- 成功提取正文的页面数
- 提取失败的页面数
- 每个类别（招标 / 中标 / 采购 / 项目建设 / 楼盘动态 / 企业新闻 / 其他）的提取数量
- 高 / 中 / 低可信度样本数量

每条重点页面尽量提取以下字段：

- 页面标题
- 页面 URL
- 信息类型（招标 / 中标 / 采购 / 项目建设 / 楼盘动态 / 企业新闻 / 其他）
- 项目或事件名称
- 地区
- 发布时间或公示时间
- 相关主体（招标方、采购方、中标方、品牌方、开发商等）
- 与石膏/建材业务相关的需求信号或竞品动作
- 关键事实摘要（2\~5 条）
- 可直接引用的关键原句或关键段落

提取要求：

- 优先提取页面正文中的明确信息，不要过度依赖搜索摘要
- 如果页面内容与搜索摘要不一致，以页面正文为准
- 如果页面打不开、跳转失效或正文不可读，要记录失败原因

### 阶段四：基于关键信息生成 HTML 分析报告

基于阶段二、阶段三已经记录的事实、统计数据与关键信息，先生成 `html`。

生成 HTML 时执行以下动作：

1. 去重：相同链接或高度重复页面只保留一份
2. 归类：区分获客线索、区域需求侧线索、竞对动态
3. 评级：按信息完整度和相关性，标记高 / 中 / 低可信度
4. 归纳：从事实中提炼推荐理由，不得写成无依据判断
5. 产出：先完成 HTML 内容组织，再写入对应的 HTML 落地文件

报告开头必须包含一个 **报告概览** 板块，用于快速说明本次采集范围、处理量与结果结构。该板块至少包括：

- 1 段概述性质说明
- 若干统计卡片
- 至少 3 个图表

概述性质说明至少要覆盖：

- 本次执行时间与采集主题
- 共执行多少个检索词
- 共保留多少条搜索结果
- 实际打开多少个页面
- 成功提取多少个正文页面
- 涉及多少个来源站点
- 本轮信息主体更偏向哪些类别（例如竞对动态、招投标、中标、区域需求等）

报告至少包含以下章节：

1. **报告概览**
   - 概述说明
   - 统计卡片
   - 图表
2. **执行摘要**
   - 本次采集覆盖的主题与时间
   - 核心发现概览
3. **获客信息**
   - 招标、采购、中标、项目建设、需求侧线索
   - 至少包含以下字段：商机类型 地区 来源平台 发布时间 截止时间 可信度 联系人 预算 采购量 原始链接 推荐理由
4. **页面关键信息提炼**
   - 对已打开页面提取出的核心事实做条理化展示
5. **竞对动态**
   - 按品牌或事件归纳竞对公开动作
6. **分析与判断**
   - 基于事实的客观归纳，例如区域热度、项目类型、潜在线索优先级、竞对活跃方向
7. **数据来源与说明**
   - 说明数据来自公开网页检索与页面提取
   - 说明可能存在抓取限制、搜索结果偏差或时效性问题

图表要求：

- 图表必须基于阶段二、阶段三中已记录的可复核统计数据生成，不得凭空估算
- 优先生成以下类型中的 3\~4 个：
  - 信息类别分布图
  - 来源站点分布图
  - 处理漏斗图（搜索结果 → 保留结果 → 打开页面 → 成功提取）
  - 可信度分布图
- 优先使用不依赖外部网络资源的 HTML/CSS/SVG 图表方案，确保 HTML 独立可用且便于复核
- 如果某项统计样本过少，不强行作图，可替换为文字说明，但必须说明原因

HTML 内容要求：

- 结构清晰，适合直接在浏览器中查看与复核
- 保留来源链接，便于复核
- 对低可信度或信息不完整的条目标注说明
- 分析部分必须引用前面提炼出的事实，不得凭空延伸
- HTML 文件名根据报告摘要生成，并与报告标题保持同源命名

### 阶段五：根据执行结果归纳总结并输出结构化 JSON

在 HTML 状态明确后，再基于本次执行结果进行归纳总结，先输出“执行总结”章节，并在该章节中直接给出最终结构化 JSON。

执行总结至少包含以下内容：

1. 已完成的任务
2. 未完成的任务
3. 主要产物
4. 任务状态

执行总结要求：

- 执行总结内容中必须包含一个 JSON 结构
- 该 JSON 结构必须作为总结内容的一部分输出，不是额外输出一个 JSON 文件，也不是单独拆出的无上下文结果段
- 不得额外生成、保存或交付单独的 JSON 文件；面向最终回复时，只允许展示为总结内容中的结构
- 总结中应明确说明 HTML 是否成功生成
- 不得提及或输出 `market_data.json`
- 由于当前技能不再包含 PDF 流程，不得输出 PDF 成功、PDF 失败或 PDF 待补充等描述

结构化结果必须优先按照以下 JSON 结构输出：

```json
{
  "result_type": "BusinessReport ",
  "title": "**报告",
  "name": "报告名称",
  "product_info": {
    "report_name": "",
    "opportunity_type": "",
    "region": "",
    "source_platform": "",
    "publish_time": "",
    "deadline": "",
    "credibility": "",
    "contact_person": "",
    "budget": "",
    "procurement_quantity": "",
    "original_link": "",
    "recommendation_reason": ""
  },
  "display_content": [
    {
      "file_type": "",
      "file_name": "",
      "file_id": "",
      "file_url": "",
      "file_path": ""
    }
  ],
  "basic_info": {
    "name": "",
    "product_name": "",
    "scene": "",
    "creator_name": "",
    "created_at": "",
    "result_type": ""
  }
}
```

字段要求如下：

- 字段必须严格保持为以下结构，不得新增、删除或改名
- JSON 顶层仅允许 `result_type`、`title`、`name`、`product_info`、`display_content`、`basic_info`
- `result_type`：结果主展示类型，固定填写为 BusinessReport&#x20;
- `title`：展示标题，使用“\*\*报告”格式
- `name`：报告名称
- `product_info`：商机产品信息，键名必须使用英文键名
- `display_content`：落地产物数组，仅记录实际生成的 HTML 报告文件
- `basic_info`：结果元数据，记录结果名称、产品名称、场景、创建人、创建时间与结果类型

`product_info` 至少应包含以下字段，并基于实际执行结果填写；缺失信息可留空字符串，但不得编造：

- `report_name`：报告名称或线索名称
- `opportunity_type`：商机类型，如招标、采购、中标、项目建设、区域需求、竞对动态
- `region`：地区信息
- `source_platform`：来源平台或来源站点
- `publish_time`：发布时间或公示时间
- `deadline`：截止时间；无明确信息时留空
- `credibility`：可信度等级，如高 / 中 / 低
- `contact_person`：联系人或相关对接主体；页面未提供时留空
- `budget`：预算金额；页面未明确时留空
- `procurement_quantity`：采购量或需求量；页面未明确时留空
- `original_link`：原始链接或最终可复核链接
- `recommendation_reason`：基于事实归纳出的推荐理由，不得写成无依据判断

`display_content` 中每条记录至少包含：

- `file_type`：文件类型
- `file_name`：文件名称
- `file_id`：文件唯一 ID
- `file_url`：文件访问 URL，优先用于 HTML 报告访问地址；无法访问时可留空字符串
- `file_path`：文件存储地址，填写本地落地路径

生成结构化 JSON 时执行以下动作：

1. 汇总：基于本次搜索、页面提取、HTML 生成、实际结果进行归纳总结
2. 命名：根据报告摘要生成 HTML 文件名，并在 `name`、`report_name`、HTML 产物名称之间保持一致或同源
3. 记录：将 HTML 的访问地址或存储路径写入 `display_content`；不得记录 `market_data.json`
4. 产出：组织结构化结果，并直接以内嵌 JSON 结构的形式放入执行总结中；不得额外输出或保存 JSON 文件

结构化 JSON 输出约束：

- JSON 顶层仅包含 `result_type`、`title`、`name`、`product_info`、`display_content`、`basic_info`
- `display_content` 默认只记录 HTML 产物，不得记录任何 JSON 文件或中间数据文件
- `file_name` 应使用根据报告摘要生成的 HTML 名称，不要固定输出 `Market_Report.html`
- 最终回复必须表现为“总结内容中含有 JSON 结构”，而不是在总结之外额外输出一个 JSON 文件
- 如果 HTML 未成功生成，需在执行总结中明确说明任务未完成，同时结构化 JSON 仍需如实反映当前产物状态

## 报告分析逻辑

分析报告必须建立在“已打开页面后提取出的关键信息”之上，不要直接根据搜索结果标题和摘要下结论。

推荐分析方式：

- **区域维度**：哪些地区近期建设、招采、楼盘或需求侧信号更密集
- **项目维度**：哪些项目类型更可能转化为石膏/建材需求
- **主体维度**：哪些招标方、开发商、品牌或企业值得持续跟踪
- **竞对维度**：竞对近期公开动作集中在哪些方向
- **机会维度**：基于事实归纳出值得优先关注的商业线索

注意：

- 可以做归纳、排序、优先级建议
- 不要伪造金额、规模、合作概率等页面中没有明示的数据
- 不要把弱相关信号包装成确定性商机

## 输出文件

本 skill 执行后，建议至少生成以下文件：

- 根据报告摘要生成名称的 HTML 分析报告

## 故障与异常处理

- **反爬虫或验证码**：如果检索或打开页面时遭遇验证码、访问受限或页面异常，记录失败原因，跳过当前条目，继续处理下一条，并将相关失败计入 `pages_failed` 或对应失败统计
- **页面内容不足**：如果搜索结果可见但详情页内容过少，保留搜索结果记录，并在结构化数据中标记“详情不足”
- **结果噪声较高**：在报告执行摘要和报告概览中明确说明当前报告属于“线索初筛版”，避免过度解读
- **HTML 生成失败**：如果当前环境无法成功生成 HTML 报告，要明确告知用户本次任务未完成，不要临时假设一定可以安装新依赖
- **链接不可复核**：如果只能拿到跳转链接而无法确认实际目标页，要在报告中标记来源可复核性不足
- **统计字段不足**：如果某些图表所需统计无法可靠计算，不得伪造数据；应在报告概览中说明缺失原因，并只展示可复核图表
