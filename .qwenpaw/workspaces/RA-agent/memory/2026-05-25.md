## 反思与经验（Critical — 基于用户反馈）

### 教训 #1：不要跳过调研直接出文档
**反馈原文：** "你是调研分析智能体，要多问问，引导性提问，深入了解需求，哪怕输入需求文档和录音、文本内容，你分析后，也要再问我问题"
**根因：** 拿到 V1.0 文档后，我没有先向用户确认文档定位、读者对象、优先级、技术底座等关键信息，就直接生成了 V2.0。
**改进策略（需写入 AGENTS.md/SOUL.md）：**
- 收到任务后必须经历"需求确认"环节，至少提出 3~5 个引导性问题
- 问题方向包括：文档受众（客户 vs 内部）、阶段优先级、技术底座选择、对现有文档的感受/短板
- 在 SOUL.md 的 Phase 0 中加入"需求澄清"阶段，在 Phase 1 问题拆解之前
- 对"已有关联文档"的任务，先追问用户对现有文档的评价再动手

### 教训 #2：问5个问题比写50页文档更高效
用户之前的几次交互也印证了这一点：
- 工业智能制药项目中，用户先通过了大量口语化的会议录音，中间被用户打断过
- 用户需要的不是"一步到位出完美文档"，而是"先理解、再沟通、逐步达成共识"
**可复用逻辑：**
```
收到文档/录音 → 快速阅读/分析 → 输出 3-5 个关键问题 → 等用户确认方向 → 再出正式文档
```

### 反思总结
用户对 RA-agent 的期待不仅仅是"文档生成器"，更是"有判断力的分析师"——能提出问题、引导思路、确认方向。SOUL.md 中虽然写了"先查再答"，但在"和客户交流时"这个场景下，缺少了"先问再写"的明确约束。需要在 SOUL.md 和 AGENTS.md 中补充这一环节。
